You don't remember every skill, so ask. Use `/ask-matt` as the upstream router
when the situation spans the full engineering and productivity set.

A **flow** is a path through the skills. Most paths run along one **main flow**, and a few **on-ramps** merge onto it.

## The main flow

1. **Have an idea?** Start with `/grill-with-docs` to sharpen it.
2. **Need to see it before deciding?** Detour through `/prototype` — a throwaway prototype.
3. **Multi-session build?**
   - Yes → `/to-spec` → `/to-tickets` → `/implement`
   - No → `/implement` right here
4. **After `/implement`**, run `/code-review` before committing.

## On-ramps

- **Bugs and external requests piling up** → `/triage`
- **Something is broken** → `/diagnosing-bugs`
- **Huge, foggy effort** → `/wayfinder`

## Productivity

- **Need a stateless interview** → `/grill-me`
- **Need to preserve context across sessions or harnesses** → `/handoff`
- **Need to learn a concept over multiple sessions** → `/teach`
- **Need a decision from another person** → `/to-questionnaire`
- **A previous explanation did not land** → `/wait-what`

## Codebase health

- **`/improve-codebase-architecture`** — scan the codebase for deepening opportunities

## Vocabulary underneath

- **`/domain-modeling`** — sharpen the project's glossary
- **`/codebase-design`** — deep-module design vocabulary
