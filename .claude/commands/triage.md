Move issues on the project issue tracker through a small state machine of triage roles. Read `docs/agents/issue-tracker.md` and `docs/agents/triage-labels.md` for the exact workflow.

## Roles

- **Category:** `bug` or `enhancement`
- **State:** `needs-triage`, `needs-info`, `ready-for-agent`, `ready-for-human`, `wontfix`

## Invocation

Interpret the user's request:

- "Show me anything that needs my attention"
- "Let's look at #42"
- "Move #42 to ready-for-agent"
- "What's ready for agents?"

## Show what needs attention

Query GitHub Issues and present three buckets, oldest first:

1. Unlabeled
2. `needs-triage`
3. `needs-info` with reporter activity since the last triage notes

## Triage a specific issue or PR

1. Gather context: read body, comments, labels, author, dates. For a PR, read the diff too.
2. Run two checks:
   - **Redundancy:** search the codebase for existing implementations of the requested behavior by domain concept.
   - **Prior rejection:** check `.out-of-scope/*.md` if it exists.
3. Verify the claim: reproduce a bug, run tests for a PR.
4. If needed, run the `domain-modeling` skill to grill the request into shape.
5. Apply the outcome with the correct label and a comment.

## Disclaimer

Every comment or issue posted during triage must start with:

```
> *This was generated by AI during triage.*
```
